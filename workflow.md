## THE SEVEN STAGES

### STAGE 1: DEFINE
Before writing the prompt, define the task.

Questions to answer:
1. What specific output do I want?
2. Who is the audience?
3. What format should the output take?
4. What are the constraints?
5. How will I know if the output is good?

**Rule:** Do not write a single word of the prompt until all five questions are answered.

---

### STAGE 2: DRAFT
Write a first-version prompt using these components:
- Context: background the model needs
- Task: the specific action (use an action verb)
- Format: how the output should look
- Constraints: rules the output must follow
- Role: a persona for the model (if relevant)
- Examples: demonstrations (if needed)
- Tone: the stylistic register
- Negative instructions: what NOT to do

**Rule:** A 2-minute draft is better than a perfect prompt you never write.

---

### STAGE 3: TEST
Run the prompt. Read the entire output before evaluating.

**Rule:** No mid-read interruptions. Read the full result first.

---

### STAGE 4: EVALUATE
Score the output:

| Criterion | Score (1-5) | Note |
|---|---|---|
| Task completion | | Did it do what I asked? |
| Format compliance | | Correct format? |
| Accuracy | | Factually correct? |
| Tone | | Right style? |
| Length | | Right length? |
| Usefulness | | Would I use this? |

**Rule:** Be specific. "Wrong format because used bullets instead of paragraphs" — not "bad."

---

### STAGE 5: REFINE
Identify the single weakest point. Fix it. Test again.

**Rules:**
1. One change per iteration
2. Save every version (v1, v2, v3...)
3. Know why you made each change

---

### STAGE 6: DOCUMENT
When the prompt performs consistently, document it:
- Complete prompt text
- Context it was designed for
- What it produces
- Its limitations
- Refinement history

**Rule:** Document the same day. Memory is unreliable.

---

### STAGE 7: REUSE
Convert good prompts into templates using [VARIABLE] notation.

**Rule:** Every documented prompt is a permanent asset.

## PROMPT ANATOMY REFERENCE

| Component | Purpose | Example |
|---|---|---|
| Context | Situational background | "You are summarising for a non-expert audience" |
| Task | The action | "Explain what a neuron is" |
| Format | Output structure | "Three paragraphs, no bullet points" |
| Constraints | Rules | "Under 200 words. No jargon." |
| Examples | Demonstrations | Show 2–3 input/output pairs |
| Tone | Stylistic register | "Conversational and encouraging" |
| Negative instructions | What NOT to do | "Do not start with 'Certainly'" |
| Role | Model persona | "You are a senior software engineer" |
