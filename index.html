Prompt Engineering Workflow

AI & Automation | Year 1: Foundations | Cycle 1 | August 17, 2026
01
DEFINE
Before writing a prompt, define the task precisely.
Answer these five questions:

1. What specific output do I want?
2. Who is the audience?
3. What format should the output take?
4. What are the constraints?
5. How will I know if the output is good?
Rule: Do not write the prompt until all five are answered.
02
DRAFT
Write a first-version prompt using the eight components.
Context · Task · Format · Constraints · Role · Examples · Tone · Negative instructions
Rule: A 2-minute draft beats a perfect prompt you never write.
03
TEST
Run the prompt. Read the complete output before evaluating.
Do not interrupt mid-read. Observe everything the model produces — including what it did not produce.
Rule: Full output first. Evaluation second.
04
EVALUATE
Score the output against the criteria you defined in Stage 1.
Task completion · Format compliance · Accuracy · Tone · Length · Usefulness
Rule: Be specific. "Wrong format because used bullets" — not "bad."
05
REFINE
Fix the single weakest point. Test again.
Save every version. Change one thing per iteration. Know why you made each change.
Rule: One change per iteration. Always.
06
DOCUMENT
Record every prompt that performs consistently well.
Save: full prompt text · context · output type · limitations · refinement history
Rule: Document the same day. Memory is unreliable.
07
REUSE
Convert good prompts into templates using [VARIABLE] notation.
Every documented prompt is a permanent asset. A 1,825-day prompt library is more valuable than any single output.
Rule: Template first, personalise second.

Prompt Anatomy — Eight Components

Component Purpose Example
Context Situational background the model needs "You are summarising for a non-expert audience"
Task The specific action with an action verb "Explain what a neuron is"
Format How the output should be structured "Three paragraphs. No bullet points."
Constraints Rules the output must follow "Under 200 words. No jargon."
Examples Demonstrations of the pattern you want 2–3 input/output pairs
Tone Stylistic register "Conversational and encouraging"
Negative instructions What NOT to produce "Do not start with 'Certainly'"
Role Persona or identity for the model "You are a senior software engineer"
